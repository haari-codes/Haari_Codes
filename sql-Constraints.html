🔎 Lesson 10: SQL Constraints

Haari_Codes | Rules that keep database data valid and reliable

1. What Are SQL Constraints?

SQL constraints are rules applied to table columns or tables to maintain the accuracy, validity, and integrity of data.

For example, a student's ID should not be empty or repeated. A constraint can enforce this rule automatically.

CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE
);

Remember: Constraints help prevent invalid data from entering a table.

2. Types of SQL Constraints

ConstraintPurpose
NOT NULLPrevents a column from storing NULL values.
UNIQUEPrevents duplicate values in a column or column combination.
PRIMARY KEYUniquely identifies each row; cannot contain NULL.
FOREIGN KEYLinks a column to a key in another or the same table.
CHECKRequires values to satisfy a condition.
DEFAULTProvides a value when an insert omits that column.

3. NOT NULL

NOT NULL ensures that a column must have a value. It cannot be left as NULL.

CREATE TABLE Students (
    id INT,
    name VARCHAR(50) NOT NULL
);

Here, name must contain a value when inserting a row.

INSERT INTO Students (id, name)
VALUES (1, 'Anu');

An empty string is not the same as NULL. NOT NULL alone does not prevent empty text.

4. UNIQUE

UNIQUE prevents duplicate values in a column or a specified combination of columns.

CREATE TABLE Users (
    user_id INT PRIMARY KEY,
    email VARCHAR(100) UNIQUE
);

Two users cannot have the same non-NULL email value under this constraint.

You can also apply UNIQUE to multiple columns:

CREATE TABLE Enrollments (
    student_id INT,
    course_id INT,
    UNIQUE (student_id, course_id)
);

This prevents the same student-course combination from being entered twice.

5. PRIMARY KEY

A PRIMARY KEY uniquely identifies every row in a table. It combines uniqueness with NOT NULL.

CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50)
);
  • Duplicate primary-key values are not allowed.
  • NULL primary-key values are not allowed.
  • A table has only one primary-key constraint, but that key can contain multiple columns.

Example of a composite primary key:

CREATE TABLE Marks (
    student_id INT,
    subject_id INT,
    mark INT,
    PRIMARY KEY (student_id, subject_id)
);

6. FOREIGN KEY

A FOREIGN KEY maintains referential integrity by requiring a matching referenced key, subject to the database's NULL and constraint rules.

CREATE TABLE Departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(50)
);

CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    department_id INT,
    FOREIGN KEY (department_id)
        REFERENCES Departments(department_id)
);

In this example, a non-NULL department ID in Students must match an existing department.

Referential actions

  • ON DELETE CASCADE: Deleting a referenced parent row deletes matching child rows.
  • ON DELETE SET NULL: Sets the child foreign-key value to NULL, if allowed.
  • ON DELETE RESTRICT: Prevents deleting a referenced parent row while dependent rows exist. Exact behavior can vary by database.
FOREIGN KEY (department_id)
REFERENCES Departments(department_id)
ON DELETE SET NULL

For SET NULL, the foreign-key column must allow NULL. Foreign-key support and syntax depend on the database system.

7. CHECK

CHECK requires a value to satisfy a condition.

CREATE TABLE Students (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT CHECK (age >= 16),
    mark INT CHECK (mark BETWEEN 0 AND 100)
);

Here, age must be at least 16 and mark must be between 0 and 100.

Named table-level example:

CREATE TABLE Products (
    product_id INT PRIMARY KEY,
    price DECIMAL(10,2),
    CONSTRAINT chk_price
        CHECK (price >= 0)
);

CHECK behavior differs across database versions. Modern MySQL versions enforce CHECK constraints; older versions may parse but ignore them. NULL handling also matters, so combine CHECK with NOT NULL when a value is required.

8. DEFAULT

DEFAULT supplies a value when an INSERT statement does not provide one for that column.

CREATE TABLE Students (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    city VARCHAR(50) DEFAULT 'Unknown'
);
INSERT INTO Students (id, name)
VALUES (1, 'Meera');

The city value will be Unknown.

Inserting an explicit NULL is different from omitting the column. A DEFAULT does not automatically replace an explicitly supplied NULL.

9. Naming and Modifying Constraints

You can name a constraint using CONSTRAINT.

CREATE TABLE Employees (
    employee_id INT,
    salary DECIMAL(10,2),
    CONSTRAINT pk_employee PRIMARY KEY (employee_id),
    CONSTRAINT chk_salary CHECK (salary >= 0)
);

To add a constraint to an existing table, use ALTER TABLE. Exact syntax varies by database.

ALTER TABLE Employees
ADD CONSTRAINT chk_salary_positive
CHECK (salary >= 0);

Example in MySQL to add a foreign key:

ALTER TABLE Students
ADD CONSTRAINT fk_student_department
FOREIGN KEY (department_id)
REFERENCES Departments(department_id);

Dropping constraints is database-specific. In MySQL, a named foreign key can be dropped using ALTER TABLE ... DROP FOREIGN KEY constraint_name. Other constraints may use DROP CHECK, DROP INDEX, or other syntax depending on the constraint and database version.

Before adding a constraint, check existing data. Invalid existing rows can cause the operation to fail.

10. Common Mistakes

  • Using UNIQUE when the row needs a primary key.
  • Assuming DEFAULT replaces every explicit NULL.
  • Adding a foreign key before creating the referenced table or key.
  • Using SET NULL on a foreign-key column defined as NOT NULL.
  • Assuming every database handles CHECK constraints identically.
  • Trying to add a constraint when existing rows violate its rule.

Quick Revision

  • NOT NULL: Value is required.
  • UNIQUE: Prevents duplicate key values.
  • PRIMARY KEY: Uniquely identifies each row.
  • FOREIGN KEY: Maintains relationships between tables.
  • CHECK: Enforces a condition.
  • DEFAULT: Supplies a value when a column is omitted.
