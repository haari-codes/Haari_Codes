Lesson 10: Hashing

1. What Is Hashing?

Hashing is a technique used to store and retrieve data efficiently by converting a key into an index using a hash function.

The index identifies where the data should be stored in a hash table.

Example

Suppose we have a hash table with 10 positions, numbered 0 to 9, and we want to store the key 42.

Using the simple hash function:

h(key) = key % table_size

For key 42:

h(42) = 42 % 10
      = 2

Therefore, key 42 is assigned to index 2.

Hashing can make search, insertion and deletion very fast on average, but performance depends on the hash function, collisions and table load.

2. Important Terminology

  • Key: The value used to identify or locate a record.
  • Hash function: A function that maps a key to a table index.
  • Hash table: A data structure that stores key-value entries using hash-based indexing.
  • Hash value: The result produced by a hash function.
  • Collision: When two different keys map to the same table index.
  • Bucket: A table position that may hold one or more entries, depending on the collision-handling method.
  • Load factor: The number of stored entries divided by the number of table buckets.

For example, with 7 stored entries and 10 buckets:

Load factor = 7 / 10 = 0.7

3. Hash Function

A hash function converts a key into a valid table index. A good hash function distributes keys reasonably evenly across the table.

Common simple methods

A. Division method

h(key) = key % table_size

Example: h(27) = 27 % 10 = 7.

B. Mid-square method

Square the key and select some digits from the middle of the result to form the hash value. The selected digits must be mapped to a valid table index.

C. Folding method

Divide the key into parts and combine those parts to calculate a hash value.

These are common teaching examples. Real systems may use more sophisticated hash functions depending on the keys and security requirements.

4. What Is a Collision?

A collision occurs when different keys produce the same index.

Suppose the table size is 10:

h(key) = key % 10

h(22) = 22 % 10 = 2
h(42) = 42 % 10 = 2

Both keys map to index 2. The hash table needs a collision-resolution technique to store both values.

5. Collision Resolution Techniques

A. Separate Chaining

Each table position stores a collection of entries, often represented by a linked list or another suitable container.

For keys 22, 42 and 32, using key % 10:

Index 2: 22 -> 42 -> 32

All three keys have the same hash index and are stored in the same chain.

Advantages

  • Multiple keys can be stored at one index.
  • Insertion is straightforward.
  • The table can store more entries than its number of buckets.

Disadvantages

  • Requires extra storage for the chains.
  • Long chains can make searching slower.

B. Open Addressing

In open addressing, all entries are stored inside the table itself. If an index is occupied, the algorithm probes other positions to find an available slot.

1. Linear Probing

Check the next position one by one until an empty slot is found.

index = (h(key) + i) % table_size

Here, i starts at 0 and increases after each unsuccessful attempt.

Example with table size 10:

  • Insert 22 at index 2.
  • Insert 42. Index 2 is occupied, so try index 3.
  • Insert 32. Index 2 is occupied, then index 3, so try index 4.

Result:

Index 2: 22
Index 3: 42
Index 4: 32

Limitation: Linear probing can cause primary clustering, where long groups of occupied positions build up.

2. Quadratic Probing

Instead of checking consecutive positions, the algorithm uses increasing quadratic offsets.

index = (h(key) + i * i) % table_size

The precise formula and table size must be chosen carefully to ensure the probing sequence can reach enough positions.

3. Double Hashing

A second hash function determines the step size used when the first position is occupied.

index = (h1(key) + i * h2(key)) % table_size

This can reduce clustering when the functions and table size are chosen appropriately.

6. C++ Example: Simple Hash Function

This example calculates the index for each key using the division method.

#include <iostream>
using namespace std;

int hashFunction(int key, int tableSize) {
    return key % tableSize;
}

int main() {
    int tableSize = 10;
    int keys[] = {22, 42, 17, 35};
    int n = 4;

    for (int i = 0; i < n; i++) {
        cout << "Key: " << keys[i]
             << ", Index: "
             << hashFunction(keys[i], tableSize)
             << endl;
    }

    return 0;
}

Output:

Key: 22, Index: 2
Key: 42, Index: 2
Key: 17, Index: 7
Key: 35, Index: 5

Notice that keys 22 and 42 have the same index. That is a collision.

7. C++ Example: Hash Table with Linear Probing

This simple example stores integer keys in a fixed-size table. It handles collisions using linear probing.

#include <iostream>
using namespace std;

const int SIZE = 10;
const int EMPTY = -1;

int table[SIZE];

void initialize() {
    for (int i = 0; i < SIZE; i++)
        table[i] = EMPTY;
}

bool insertKey(int key) {
    int start = key % SIZE;

    for (int i = 0; i < SIZE; i++) {
        int index = (start + i) % SIZE;

        if (table[index] == EMPTY) {
            table[index] = key;
            return true;
        }

        if (table[index] == key)
            return true;
    }

    return false;
}

int searchKey(int key) {
    int start = key % SIZE;

    for (int i = 0; i < SIZE; i++) {
        int index = (start + i) % SIZE;

        if (table[index] == EMPTY)
            return -1;

        if (table[index] == key)
            return index;
    }

    return -1;
}

int main() {
    initialize();

    insertKey(22);
    insertKey(42);
    insertKey(32);
    insertKey(17);

    for (int i = 0; i < SIZE; i++) {
        cout << i << ": ";
        if (table[i] == EMPTY)
            cout << "Empty";
        else
            cout << table[i];
        cout << endl;
    }

    int key = 32;
    int position = searchKey(key);

    if (position != -1)
        cout << key << " found at index "
             << position << endl;
    else
        cout << key << " not found" << endl;

    return 0;
}

Output:

0: Empty
1: Empty
2: 22
3: 42
4: 32
5: Empty
6: Empty
7: 17
8: Empty
9: Empty
32 found at index 4
Important limitation: This teaching example uses -1 to mark an empty slot, so -1 cannot be stored as a key. It also does not implement deletion. With deletion in open addressing, simply clearing a slot can break later searches; implementations commonly use a special deleted marker.

8. Time Complexity

OperationAverage caseWorst case
SearchO(1)O(n)
InsertionO(1)O(n)
DeletionO(1) expected with suitable handlingO(n)

These are typical expected and worst-case bounds for common hash-table designs, not guarantees for every implementation.

Average-case operations can be close to O(1) when the hash function distributes keys well and the load factor is controlled. Many collisions can degrade performance to O(n).

9. Applications of Hashing

  • Fast lookup in dictionaries and maps.
  • Database indexing and lookup structures.
  • Caching frequently accessed data.
  • Checking whether a value has already been seen.
  • Counting the frequency of words or numbers.
  • Symbol tables in compilers.
  • Integrity checks using cryptographic hash functions.

A cryptographic hash function is designed for security properties such as resistance to collisions and preimage attacks. The simple modulo function used in this lesson is not a cryptographic hash function.

10. Advantages and Disadvantages

Advantages

  • Fast average-case lookup, insertion and deletion.
  • Useful for storing key-value pairs.
  • Works well for dictionaries, caches and frequency counting.

Disadvantages

  • Collisions must be handled.
  • Worst-case operations may take O(n).
  • Hash tables do not naturally keep keys sorted.
  • Resizing and choosing a good hash function require care.
