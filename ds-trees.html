Lesson 8: Trees

1. What Is a Tree?

A tree is a non-linear, hierarchical data structure consisting of nodes connected by edges.

Unlike an array or linked list, tree data is organised into parent-child relationships. A tree with n nodes has n - 1 edges when it is a non-empty tree.

Example

A / \ B C / \ D E

Here, A is the root. B and C are its children. D and E are children of B.

Why use trees?

  • To represent hierarchical relationships.
  • To organise data for efficient searching.
  • To represent folders, organisation charts and decision processes.
  • To implement databases and priority queues using specialised tree structures.

2. Tree Terminology

  • Node: An individual element in a tree.
  • Root: The topmost node. It has no parent.
  • Edge: A connection between two nodes.
  • Parent: A node that has one or more children.
  • Child: A node directly connected below a parent.
  • Siblings: Nodes sharing the same parent.
  • Leaf node: A node with no children.
  • Internal node: A node with at least one child.
  • Ancestor: Any node on the path from the root to a particular node, excluding that node itself.
  • Descendant: A node below another node in its subtree.
  • Subtree: A node and all its descendants.
  • Depth: The number of edges from the root to a node.
  • Height of a node: The number of edges on the longest downward path from that node to a leaf.
  • Height of a tree: The height of its root. A single-node tree has height 0 under this convention.

In the example above, A is the root, B and C are siblings, and C is a leaf node.

3. Types of Trees

General Tree

A node can have any number of children.

Binary Tree

A tree in which each node has at most two children, commonly called the left child and right child.

10 / \ 5 20 / \ 2 7

Full Binary Tree

Every node has either zero or exactly two children.

Complete Binary Tree

Every level is completely filled except possibly the last, and the last level is filled from left to right.

Perfect Binary Tree

Every internal node has two children, and all leaves are at the same depth.

Binary Search Tree (BST)

A binary tree in which values in the left subtree are smaller than the node's value and values in the right subtree are larger, assuming distinct keys and this insertion rule.

Balanced Tree

A tree kept at a controlled height so that operations such as searching can remain efficient. AVL trees and Red-Black trees are examples of self-balancing BSTs.

4. Binary Tree Representation in C++

A common representation uses a structure or class containing the data and pointers to the left and right children.

#include <iostream>
using namespace std;

struct Node {
    int data;
    Node* left;
    Node* right;

    Node(int value) {
        data = value;
        left = nullptr;
        right = nullptr;
    }
};

int main() {
    Node* root = new Node(10);
    root->left = new Node(5);
    root->right = new Node(20);

    cout << root->data << endl;
    cout << root->left->data << endl;
    cout << root->right->data << endl;

    delete root->left;
    delete root->right;
    delete root;

    return 0;
}

Output:

10
5
20

left and right point to child nodes. nullptr means there is no child at that pointer.

5. Tree Traversal

Traversal means visiting each node in a tree in a particular order.

Consider this tree:

1 / \ 2 3 / \ 4 5

A. Inorder: Left, Root, Right (LNR)

  1. Traverse the left subtree.
  2. Visit the root.
  3. Traverse the right subtree.

Output: 4 2 5 1 3

B. Preorder: Root, Left, Right (NLR)

  1. Visit the root.
  2. Traverse the left subtree.
  3. Traverse the right subtree.

Output: 1 2 4 5 3

C. Postorder: Left, Right, Root (LRN)

  1. Traverse the left subtree.
  2. Traverse the right subtree.
  3. Visit the root.

Output: 4 5 2 3 1

D. Level Order

Visits nodes level by level from left to right. It typically uses a queue.

Output: 1 2 3 4 5

6. C++ Program for Tree Traversals

#include <iostream>
using namespace std;

struct Node {
    int data;
    Node* left;
    Node* right;

    Node(int value) {
        data = value;
        left = nullptr;
        right = nullptr;
    }
};

void inorder(Node* root) {
    if (root == nullptr) return;

    inorder(root->left);
    cout << root->data << " ";
    inorder(root->right);
}

void preorder(Node* root) {
    if (root == nullptr) return;

    cout << root->data << " ";
    preorder(root->left);
    preorder(root->right);
}

void postorder(Node* root) {
    if (root == nullptr) return;

    postorder(root->left);
    postorder(root->right);
    cout << root->data << " ";
}

int main() {
    Node* root = new Node(1);
    root->left = new Node(2);
    root->right = new Node(3);
    root->left->left = new Node(4);
    root->left->right = new Node(5);

    cout << "Inorder: ";
    inorder(root);

    cout << "\nPreorder: ";
    preorder(root);

    cout << "\nPostorder: ";
    postorder(root);

    cout << endl;

    delete root->left->left;
    delete root->left->right;
    delete root->left;
    delete root->right;
    delete root;

    return 0;
}

Output:

Inorder: 4 2 5 1 3
Preorder: 1 2 4 5 3
Postorder: 4 5 2 3 1
Memory tip: Inorder = LNR, Preorder = NLR, Postorder = LRN. The position of the root tells you the traversal name.

7. Binary Search Tree (BST)

A BST is a binary tree organised to make searching, insertion and deletion efficient when its height is reasonably small.

For distinct values:

  • Values smaller than a node go into its left subtree.
  • Values larger than a node go into its right subtree.
  • The rule applies recursively to each subtree.

Example

Insert values in this order: 10, 5, 15, 3, 7.

10 / \ 5 15 / \ 3 7

Searching for 7:

  1. Compare 7 with 10. Since 7 is smaller, go left.
  2. Compare 7 with 5. Since 7 is larger, go right.
  3. Reach 7. Target found!

Advantages of BST

  • Can support efficient searching, insertion and deletion.
  • Inorder traversal produces sorted values for a BST.
  • Can support ordered operations such as finding a minimum or maximum.

Disadvantages of BST

  • An ordinary BST can become skewed, reducing performance.
  • Implementation is more complex than an array.
  • Balancing adds extra implementation requirements.

8. Complexity of Tree Operations

OperationTypical complexity
Traverse all nodesO(n)
Search in a balanced BSTO(log n)
Insert in a balanced BSTO(log n)
Delete in a balanced BSTO(log n)
Search in a skewed BSTO(n)
Insert in a skewed BSTO(n)

Here, n is the number of nodes. BST complexity depends on tree height. Balanced BSTs keep the height around O(log n), while a skewed tree can have height O(n).

9. Applications of Trees

  • Folder and file systems.
  • HTML and XML document structure.
  • Database indexes and search structures.
  • Expression trees used in compilers and calculators.
  • Decision trees in machine learning.
  • Hierarchical organisation charts.
  • Autocomplete and dictionary lookup using specialised tree structures.
