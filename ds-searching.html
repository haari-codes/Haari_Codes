Lesson 6: Searching Algorithms

1. What Is Searching?

Searching is the process of finding a particular element or value in a collection of data.

The value we want to find is called the key or target. A searching algorithm tells us whether the element exists and, usually, its position.

Example: Finding a student's roll number in a list, locating a contact in a phone, or finding a book in a library catalogue.

Main searching algorithms: Linear Search and Binary Search.

2. Linear Search

Definition

Linear Search checks each element one by one, starting from the first element, until the target is found or the list ends.

Example

Array: [12, 7, 25, 9, 18]
Target: 9

  1. Check 12. It is not 9.
  2. Check 7. It is not 9.
  3. Check 25. It is not 9.
  4. Check 9. Target found!

The target is at index 3 in zero-based indexing, or position 4 when counting from 1.

Algorithm

  1. Start from the first element.
  2. Compare the current element with the target.
  3. If they match, return its position.
  4. Otherwise, move to the next element.
  5. If all elements are checked, report that the target was not found.

Pseudocode

LINEAR_SEARCH(A, n, key)
    for i = 0 to n - 1
        if A[i] == key
            return i
    return -1

C++ Program

#include <iostream>
using namespace std;

int main() {
    int a[] = {12, 7, 25, 9, 18};
    int n = 5;
    int key = 9;
    int position = -1;

    for (int i = 0; i < n; i++) {
        if (a[i] == key) {
            position = i;
            break;
        }
    }

    if (position != -1)
        cout << "Found at index " << position;
    else
        cout << "Element not found";

    return 0;
}

Output:

Found at index 3

Advantages

  • Simple and easy to implement.
  • Works with sorted and unsorted data.
  • Does not require extra storage for searching.

Disadvantages

  • May check every element in a large collection.
  • Usually slower than Binary Search for large, sorted arrays.

3. Binary Search

Definition

Binary Search finds a target by repeatedly dividing the search range into two halves.

Important condition: The data must be sorted in the order used by the algorithm. The example below uses ascending order.

Worked Example

Sorted array: [3, 8, 12, 17, 23, 31, 42]
Target: 23

StepLowHighMidCheck
106317 < 23, search right half
246531 > 23, search left half
344423 found!

The target is found at index 4, which is position 5 when counting from 1.

How It Works

  1. Set low = 0 and high = n - 1.
  2. Calculate the middle index: mid = low + (high - low) / 2.
  3. If the middle element equals the target, return the index.
  4. If the target is greater, search the right half by setting low = mid + 1.
  5. If the target is smaller, search the left half by setting high = mid - 1.
  6. Repeat while low <= high. If the range becomes empty, the target is absent.

Pseudocode

BINARY_SEARCH(A, n, key)
    low = 0
    high = n - 1

    while low <= high
        mid = low + (high - low) / 2

        if A[mid] == key
            return mid
        else if A[mid] < key
            low = mid + 1
        else
            high = mid - 1

    return -1

C++ Program

#include <iostream>
using namespace std;

int main() {
    int a[] = {3, 8, 12, 17, 23, 31, 42};
    int n = 7;
    int key = 23;

    int low = 0;
    int high = n - 1;
    int position = -1;

    while (low <= high) {
        int mid = low + (high - low) / 2;

        if (a[mid] == key) {
            position = mid;
            break;
        }
        else if (a[mid] < key) {
            low = mid + 1;
        }
        else {
            high = mid - 1;
        }
    }

    if (position != -1)
        cout << "Found at index " << position;
    else
        cout << "Element not found";

    return 0;
}

Output:

Found at index 4

Advantages

  • Very efficient for large, sorted arrays.
  • Reduces the search range by about half each step.

Disadvantages

  • Requires sorted data.
  • Sorting data first can take extra time if it is not already sorted.
  • It is less straightforward than Linear Search.

4. Linear Search vs Binary Search

FeatureLinear SearchBinary Search
MethodChecks elements one by oneRepeatedly halves the search range
Sorted data required?NoYes, for this method
Best timeO(1)O(1)
Average timeO(n)O(log n)
Worst timeO(n)O(log n)
Iterative extra spaceO(1)O(1)
Best suited forSmall or unsorted listsLarge, sorted arrays

Complexity reminder: n represents the number of elements. O(n) means the work may grow proportionally with the number of elements. O(log n) grows much more slowly because the search range is halved each step.

5. Applications of Searching

  • Finding a contact in a contact list.
  • Searching student records using roll numbers.
  • Finding an item in a database or catalogue.
  • Looking up words in a dictionary.
  • Searching for a file or record by its name or ID.
